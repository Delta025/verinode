# Verinode

An interpretable, verifiable AI knowledge system that uses explicit knowledge graphs with confidence tracking, provenance, and multi-hop reasoning — designed as a structured, auditable alternative to opaque neural network weights.

> **verinode** (noun): a hypothesized physical or biochemical trace of memory in the brain. Verinode makes AI knowledge explicit, traceable, and verifiable — every fact has a source, every conclusion has a reasoning chain, and every confidence score has a mathematical derivation.

## Project Goals

1. **Explicit Knowledge Representation**: Replace implicit knowledge stored in neural network weights with a transparent graph of facts, dependencies, and confidence scores.
2. **Verifiability and Provenance**: Every fact traces back to its source. Experts can audit individual claims and follow reasoning chains.
3. **Confidence-Aware Reasoning**: All answers include confidence bounds derived from source quality, inference depth, and evidence convergence.
4. **Resilience to AI Vulnerabilities**: Defend against data poisoning, hallucination, subliminal learning, and disinformation by grounding AI output in verified, auditable knowledge.
5. **Updatability**: Modify individual facts, sources, or confidence scores without retraining an entire model.

## Research Motivation

Modern AI systems face a growing set of vulnerabilities that all share a common root: **knowledge stored in neural network weights is opaque, unauditable, and unverifiable**. This architectural gap enables a range of attacks:

- **Data poisoning**: Adversaries inject malicious samples into training data to corrupt model behavior. Even 0.001% of poisoned training tokens can compromise a medical LLM in ways that clinicians cannot detect (Alber et al., *Nature Medicine* 2025). Clean-label attacks craft poisoned samples that pass human inspection (Turner, Tsipras & Madry 2019).
- **Subliminal learning**: Models trained on data generated by another model can inherit hidden behavioral traits through non-semantic statistical patterns, even when explicit references are filtered out — including misalignment (Cloud et al. 2025, arXiv:2507.14805). No content filter can detect these signals.
- **Hallucination**: LLMs generate confident but false information as a natural consequence of next-token prediction optimized for coherence rather than truth. Model scaling alone does not solve this (Huang et al., *ACM TOIS* 2025). There is no internal mechanism to distinguish fact from fiction.
- **Prompt injection**: Adversarial inputs override system instructions or trigger unintended behaviors. Indirect injection through documents and web pages makes any LLM with tool access vulnerable (OWASP LLM Top 10, 2025).
- **Disinformation at scale**: Generative AI produces synthetic misinformation faster than fact-checkers can verify it. Model supply chain attacks can corrupt pre-trained models to propagate false information in normal operation.

Across all of these, a consistent pattern emerges: **attacks exploit the gap between statistical pattern-matching and grounded truth**. Data poisoning corrupts the patterns. Prompt injection hijacks pattern-following behavior. Subliminal learning propagates hidden patterns between models. Hallucination is the natural consequence of pattern-matching without verification.

Verinode explores whether **explicit knowledge graphs with confidence tracking, provenance, and contradiction detection** can provide the structured verification layer that neural approaches fundamentally lack. Rather than replacing LLMs, Verinode acts as an independent knowledge substrate — every claim can be decomposed into assertions and verified against confidence-weighted facts with traceable sources. Claims contradicting high-confidence established knowledge are flagged. Novel claims entering empty domains are marked as provisional. Anomalous confidence patterns signal potential contamination.

This approach draws on principles from cybersecurity: anomaly detection (intrusion detection), provenance tracking (chain of custody), multiple validation layers (defense in depth), and calibrated trust scoring (trust but verify).

For detailed research notes and references, see [docs/research.md](docs/research.md).

## Quick Start

```bash
# Install core dependencies
pip install numpy sentence-transformers ollama click rich

# Install Web UI dependencies
pip install fastapi uvicorn[standard]

# Optional: FAISS for fast vector search (falls back to numpy brute-force)
pip install faiss-cpu

# Install and start Ollama (https://ollama.com/download)
# Then pull a model:
ollama pull qwen3:14b

# Run unit tests (no Ollama server needed)
pytest tests/

# Run integration tests (requires running Ollama server + model)
pytest tests/ --run-integration

# Run the chemistry demo (no Ollama needed)
python examples/chemistry_demo.py

# Run the pipeline demo (requires running Ollama server + model)
python examples/pipeline_demo.py
```

## CLI Usage

```bash
# Ingest text into a knowledge graph
python -m src.cli ingest "Water boils at 100 degrees Celsius." --domain chemistry

# View graph statistics
python -m src.cli stats

# List nodes (filterable)
python -m src.cli list --domain chemistry --sort confidence

# Query the graph
python -m src.cli query "What is the boiling point of water?"

# Test a hypothesis
python -m src.cli hypothesis "Gold is a reactive metal"

# Verify an external claim (read-only)
python -m src.cli verify "Water boils at 50 degrees Celsius" --show-evidence

# Simulate retracting a node (what-if analysis)
python -m src.cli what-if a1b2c3d4

# Inspect a specific node (prefix match)
python -m src.cli inspect a1b2c3d4

# Detect anomalies
python -m src.cli anomalies

# Use a different graph file
python -m src.cli --graph my_graph.json stats

# Use SQLite for persistent storage (auto-detected from .db extension)
python -m src.cli --graph my_graph.db ingest "Water boils at 100C." --domain chemistry
python -m src.cli --graph my_graph.db history   # view change log

# Convert JSON graph to SQLite
python -m src.cli --graph my_graph.json save my_graph.db

# Query the graph as LLM memory (structured output)
python -m src.cli memory-query "What is the boiling point of water?" --domain chemistry

# Export a domain sub-graph
python -m src.cli export chemistry --output chemistry_export.json --threshold 0.5

# Import a sub-graph into the current graph
python -m src.cli import-graph chemistry_export.json --strategy keep_higher_confidence
```

All read-only commands (`stats`, `list`, `inspect`, `explain`, `trace`, `anomalies`, `history`, `verify`, `what-if`) work without Ollama. The `verify` and `what-if` commands use LLM contradiction detection when available but fall back to heuristics.

## Example Usage

### End-to-End Pipeline (recommended)

```python
from src.core import KnowledgeGraph, Pipeline, Source

# Create graph and pipeline (requires running Ollama server)
graph = KnowledgeGraph()
pipeline = Pipeline(graph)

# Ingest text with source metadata
result = pipeline.ingest(
    "Water boils at 100 degrees Celsius at standard atmospheric pressure. "
    "It freezes at 0 degrees Celsius.",
    source=Source(source_type="textbook", title="Chemistry 101", quality_score=0.9),
    domain="chemistry",
)
print(result.summary)  # "Extracted 2 fact(s), added 2, merged 0 duplicate(s), ..."

# Batch ingest multiple passages
batch = pipeline.ingest_batch(
    ["Gold has the symbol Au.", "Silver has the symbol Ag."],
    source=Source(source_type="textbook", title="Chemistry 101", quality_score=0.9),
)

# Query the graph
from src.core import ReasoningEngine
reasoner = ReasoningEngine()
pipeline.build_index()  # Rebuild embedding index
answer = reasoner.query(graph, "What is the boiling point of water?",
                        embedding_engine=pipeline.embedding_engine)
```

### Individual Modules

```python
from src.core import (
    KnowledgeGraph, KnowledgeNode, ConfidenceEngine,
    EmbeddingEngine, DependencyDetector, ReasoningEngine
)

# Build a graph manually
graph = KnowledgeGraph()
node = KnowledgeNode(
    text="Water boils at 100 degrees Celsius at sea level",
    confidence=0.95,
    domain="chemistry"
)
graph.add_node(node)

# Semantic search
engine = EmbeddingEngine()
engine.index_graph(graph)
results = engine.search("boiling point of water", k=5)

# Detect dependencies between nodes
detector = DependencyDetector()
deps = detector.detect_all(graph, embedding_engine=engine)
detector.apply_dependencies(deps, graph)

# Reason over the graph
reasoner = ReasoningEngine()
result = reasoner.query(graph, "What is the boiling point of water?", embedding_engine=engine)

# Propagate confidence and detect anomalies
conf = ConfidenceEngine()
conf.propagate_confidence_update(graph, node.id)
anomalies = conf.detect_anomalies(graph)
```

### Verification API

```python
from src.core import KnowledgeGraph, VerificationEngine, EmbeddingEngine

# Load an existing graph
graph = KnowledgeGraph.load("my_graph.json")
emb = EmbeddingEngine()
emb.index_graph(graph)

# Verify a claim against the graph (read-only)
verifier = VerificationEngine(graph, embedding_engine=emb)
result = verifier.verify("Water boils at 50 degrees Celsius")
print(result.verdict)      # Verdict.CONTRADICTED
print(result.confidence)   # 0.95
print(result.explanation)  # "Contradicted by 1 node(s) (max confidence: 0.95)."

# What-if: simulate retracting a node
sim = verifier.simulate_retraction(node_id)
print(sim.total_affected)       # Number of downstream nodes affected
print(sim.max_confidence_drop)  # Worst-case confidence drop
```

### LLM Memory Substrate

```python
from src.core import KnowledgeGraph, Pipeline, LLMMemory, VerificationEngine

# Build graph with pipeline (requires Ollama)
graph = KnowledgeGraph()
pipeline = Pipeline(graph)
# ... ingest facts ...

# Create LLM Memory interface
memory = LLMMemory(graph, embedding_engine=pipeline.embedding_engine,
                   reasoning_engine=ReasoningEngine(),
                   confidence_engine=ConfidenceEngine(),
                   pipeline=pipeline,
                   verification_engine=verifier)

# RECALL: Retrieve relevant facts for LLM context
result = memory.query("melting point of gold", domain="chemistry", k=5)
print(result.summary)             # One-sentence answer
print(result.overall_confidence)  # Weighted confidence across facts
print(result.coverage)            # "high", "medium", "low", or "none"

# VERIFY: Check a claim before using it
v = memory.verify("Gold melts at 500 degrees Celsius")
print(v["verdict"])      # "contradicted"
print(v["confidence"])   # 0.95

# INGEST: Submit a derived fact back to the graph
r = memory.ingest("Gold has a higher melting point than silver.",
                   source_title="LLM derivation", source_quality=0.6, domain="chemistry")
print(r.action)  # "added", "duplicate", "contradicted", or "rejected"
```

## Performance Tuning

For faster Ollama inference, set these environment variables before starting the server:

```bash
# Enable Flash Attention (faster inference, lower VRAM)
set OLLAMA_FLASH_ATTENTION=1

# Quantize KV cache (reduces VRAM usage)
set OLLAMA_KV_CACHE_TYPE=q8_0

# Allow parallel requests (matches pipeline batch parallelism)
set OLLAMA_NUM_PARALLEL=4
```

The pipeline automatically applies additional optimizations: disabled Qwen3 thinking mode (`think=False`) for 2-5x faster structured output, reduced contradiction context window, and batch-parallel LLM calls via `check_pairs_batch(max_workers=4)`.
